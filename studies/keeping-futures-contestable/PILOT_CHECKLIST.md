# Cognitive and apparatus pilot checklist

Run the cognitive pilot before freezing the main study. Pilot participants do not enter the confirmatory dataset.

## Makers: 4–6 pilot sessions

- Can participants explain each base artefact without facilitator repair?
- Do they identify at least one assumption before editor controls appear?
- Are ALPHA and BETA both usable, with no condition suffering a basic interaction failure?
- Does BETA expose semantic structure without explicitly supplying the “correct” critique?
- Does ALPHA's fixed-candidate behaviour feel understandable once the standardisation disclosure is given?
- Are three attempts sufficient to observe accept/reject/undo behaviour?
- Can participants distinguish an assumption change from visual restyling?
- Does either task exceed the intended time by more than 25%?

## Audiences: 8–12 pilot sessions

- Do closed and open protocols produce detectably different reasoning orientations?
- Can participants complete all three artefacts without fatigue dominating the final common probe?
- Does the common neutral probe remain understandable after either protocol?
- Are responses long enough to code without forcing one ideological position?
- After matching four required pre-probe text prompts, does one protocol still create substantially more protocol time, common-probe time, or response length?
- Is the comprehension item answered correctly by at least 80% in each brief during the pilot? If not, revise the stimulus before interpreting ambiguity.
- Can participants point to artefact evidence rather than only discuss the topic abstractly?

## Experts: 2 pilot reviewers

- Can reviewers apply `KEEP`, `REVISE`, and `REJECT` using purpose/audience rather than taste alone?
- Does the form leak source workflow or technical status?
- Are required revisions concrete enough to compare with technical PASS?

## Manipulation failure decisions

- If a condition is visibly broken or substantially slower because of a UI defect, repair and rerun the pilot.
- If BETA merely labels the seeded answer, revise layer names or add a neutral structure-control condition; do not interpret cueing as independent discovery.
- If ALPHA candidates routinely ignore the declared target, narrow the claim to the fixed simulator and do not generalise to contemporary generative systems.
- If open responses are only longer, retain response length and dwell time as diagnostics and withhold the interpretive-agency claim.
- If three artefacts still produce material fatigue or carryover, reduce burden through a newly frozen balanced design and rerun the audience pilot; do not change trial count during the main study.

## Freeze record

Archive:

- app and config hashes;
- protocol, preregistration, codebook, and ethics versions;
- all stimulus definitions;
- assignment tests;
- pilot issue log and decisions;
- frozen sample target and power-simulation inputs;
- manifest-building policy;
- exclusion rules.

Record every pilot session and issue using the templates under `templates/`. Copy completed pilot records to the approved, access-controlled location; do not commit them. The final `data/frozen/pilot-summary.json` must document at least 4 maker, 8 audience, and 2 expert sessions, confirm that pilot returns remain outside the main corpus, resolve all primary manipulation blockers, and carry an authorised `PROCEED` decision before main-study readiness can pass.

Passing a checklist is not the same as obtaining a favourable effect. A valid pilot may require narrowing the claim, reclassifying Study B as formative, revising the apparatus and rerunning affected pilot cells, or stopping.
